# ESP32 Embedded Firmware & Custom CPU Integration

ESP32 firmware project combining embedded-systems fundamentals with a working **custom SIMP processor integration**, **FreeRTOS**, GPIO interrupts, an SSD1306 OLED, and a buzzer.

The repository documents my progression from basic ESP32 peripheral control to executing **SIMP machine-code programs on the ESP32** and displaying processor-generated graphics on physical hardware.

---

## Project Overview

This repository contains two connected parts:

### `learning_basics/`

Incremental exercises used to learn and understand:

- ESP32 GPIO
- Button polling and debouncing
- GPIO interrupts
- FreeRTOS tasks
- FreeRTOS task notifications
- ISR-to-task synchronization

### `simp_processor_flow/`

The main integration project.

A previously developed **SIMP CPU simulator written in C** was adapted to run on the ESP32 and connected to physical peripherals.

## Working Hardware Demonstration

The ESP32 executes SIMP machine-code programs and displays the graphics generated by those programs on a physical SSD1306 OLED.

The ESP32 display code does **not** contain shape-specific drawing logic.

Instead:

```text
SIMP Program
     |
     v
Machine Code
     |
     v
SIMP CPU Execution
     |
     v
Monitor I/O Writes
     |
     v
Virtual Framebuffer
     |
     v
Generic OLED Conversion
     |
     v
Physical Display
```

This allows different SIMP programs to use the same processor and display path without modifying the OLED driver.

Programs physically demonstrated so far include:

- Filled circle
- Filled triangle

## SIMP Monitor Interface

The SIMP processor communicates with its virtual display through I/O registers:

```text
20 -> monitoraddr
21 -> monitordata
22 -> monitorcmd
```

A SIMP program draws graphics by executing normal machine instructions and writing pixel information through these monitor registers.

The ESP32 firmware then converts the resulting virtual monitor into the physical OLED framebuffer format.

---

## Display Conversion

The original SIMP monitor is:

```text
256 x 256 pixels
```

The physical SSD1306 display is:

```text
128 x 64 pixels
```

The current conversion maps each:

```text
4 x 4 SIMP pixel block
```

into one OLED pixel.

This produces a:

```text
64 x 64 image
```

which is centered horizontally on the 128x64 OLED.

## FreeRTOS & Interrupt Flow

The push button is configured as an active-low GPIO input.

A falling-edge GPIO interrupt wakes the application using a FreeRTOS task notification:

```text
Button Press
     |
     v
GPIO Interrupt
     |
     v
ISR
     |
     v
vTaskNotifyGiveFromISR()
     |
     v
Application Task Wakes
     |
     v
Debounce / Verify Button
     |
     v
Run SIMP Program
```

This allows the task to sleep while waiting for an event instead of continuously polling the button.

## Main Firmware Components

### `simp.c`

Implements the SIMP processor model, including:

- instruction fetch
- instruction decode
- execution
- register file
- program counter
- memory
- I/O registers
- virtual monitor
- cycle tracking

Main ESP32-facing functions include:

```c
simp_reset();
simp_load_program();
simp_run();
simp_get_cycles();
simp_get_monitor();
```

### `oled.c`

Implements:

- SSD1306 initialization
- I2C communication
- OLED framebuffer handling
- pixel operations
- framebuffer flushing
- SIMP-monitor-to-OLED conversion

The SIMP processor itself does not need to know anything about the physical OLED.

### `button.c`

Implements:

- GPIO input configuration
- internal pull-up
- falling-edge interrupt
- ISR handling
- FreeRTOS task notification
- debounce logic
- release detection

### `buzzer.c`

Controls the active buzzer connected to GPIO23 and provides completion feedback after program execution.

## Build & Flash

From the `simp_processor_flow/` directory with the ESP-IDF environment loaded:

```bash
idf.py set-target esp32
idf.py build
idf.py -p COM5 flash monitor
```

Replace `COM5` with the serial port used by the ESP32.
